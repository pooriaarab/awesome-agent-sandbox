# Awesome Agent Sandbox [![Awesome](https://awesome.re/badge-flat2.svg)](https://awesome.re)

> Sandboxes for running untrusted, AI-agent-generated code.

LLM agents write and execute code nobody reviewed. A sandbox is what stands between that code and your kernel, your network, and your secrets.

Every entry is one sentence followed by three badges: **how it isolates**, **how you run it**, and **who backs it**. Colour is reserved for isolation strength, so scanning the coloured column is the comparison:

![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) weakest, shares the host kernel  ·  ![intercepted kernel](https://img.shields.io/badge/intercepted%20kernel-bf8700?style=flat-square) syscalls served in user space  ·  ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) strongest, own kernel in a VM  ·  ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) you choose  ·  ![separate + TEE](https://img.shields.io/badge/separate%20%2B%20TEE-8250df?style=flat-square) hides from the host too

## Isolation Runtimes

The layer that actually provides the boundary. Everything else in this list picks one of these, so the three tier names are used throughout.

**Your own code needs a shared kernel at most. A stranger's needs a separate one.** The middle is a business decision, not a technical one.

### Shared kernel

> Same kernel as the host, fenced off with namespaces, cgroups, and syscall filters. Instant and cheap, but a kernel bug is a host compromise.

- [runc](https://github.com/opencontainers/runc) - The default container runtime, and the baseline this list measures against. Fine for code you wrote; a kernel bug is a host compromise. ![the default](https://img.shields.io/badge/the%20default-8b949e?style=flat-square) ![OCI](https://img.shields.io/badge/OCI-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/opencontainers/runc?style=flat-square&label=%20)
- [Sysbox](https://github.com/nestybox/sysbox) - Hardened runc that gives each container its own user namespace and a virtualised `/proc`. Runs Docker-in-Docker and systemd safely — the strongest option that still shares a kernel. ![Docker-in-Docker safe](https://img.shields.io/badge/Docker--in--Docker%20safe-8b949e?style=flat-square) ![Docker](https://img.shields.io/badge/Docker-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/nestybox/sysbox?style=flat-square&label=%20)
- [bubblewrap](https://github.com/containers/bubblewrap) - Unprivileged process sandboxing on namespaces and seccomp. A building block rather than a platform: both Flatpak and Anthropic's sandbox-runtime sit on top of it. ![engine under Flatpak](https://img.shields.io/badge/engine%20under%20Flatpak-8b949e?style=flat-square) ![Red Hat](https://img.shields.io/badge/Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/containers/bubblewrap?style=flat-square&label=%20)
- [nsjail](https://github.com/google/nsjail) - Namespaces, cgroups, rlimits, and seccomp-bpf behind one small binary. Common for CTF judges and untrusted build steps, where a full container runtime is overkill. ![single binary](https://img.shields.io/badge/single%20binary-8b949e?style=flat-square) ![Google](https://img.shields.io/badge/Google-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/google/nsjail?style=flat-square&label=%20)

### Intercepted kernel

> Syscalls are reimplemented in user space and never reach the host kernel. No virtualization required, which is why it wins on managed Kubernetes.

- [gVisor](https://github.com/google/gvisor) - The only production option in this tier. Its Sentry reimplements most of the Linux syscall surface in user space, so the host sees a fraction of the calls — and no virtualization is required. ![default on GKE](https://img.shields.io/badge/default%20on%20GKE-8b949e?style=flat-square) ![Google](https://img.shields.io/badge/Google-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/google/gvisor?style=flat-square&label=%20)

### Separate kernel

> Its own Linux kernel in a virtual machine. Nothing shared, so an exploit stays in the box. The baseline for code you did not write.

- [Firecracker](https://github.com/firecracker-microvm/firecracker) - The microVM that created this category and still the leanest: a minimal device model, a few MB of overhead per VM, and the snapshot support that E2B and others build pause/resume on. Reaches Kubernetes as a Kata backend. ![125ms boot](https://img.shields.io/badge/125ms%20boot-8b949e?style=flat-square) ![AWS](https://img.shields.io/badge/AWS-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/firecracker-microvm/firecracker?style=flat-square&label=%20)
- [Kata Containers](https://github.com/kata-containers/kata-containers) - Swappable VMM backends — QEMU, Firecracker, Cloud Hypervisor, Dragonball — behind a standard RuntimeClass, plus Intel TDX or AMD SEV-SNP when the host operator is in your threat model. ![most mature on K8s](https://img.shields.io/badge/most%20mature%20on%20K8s-8b949e?style=flat-square) ![OpenInfra](https://img.shields.io/badge/OpenInfra-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kata-containers/kata-containers?style=flat-square&label=%20)
- [Cloud Hypervisor](https://github.com/cloud-hypervisor/cloud-hypervisor) - Modern Rust VMM built for cloud workloads and commonly used as a Kata backend. Supports CPU and memory hotplug, which matters if you want to resize a sandbox rather than recreate it. ![Kata backend](https://img.shields.io/badge/Kata%20backend-8b949e?style=flat-square) ![Linux Foundation](https://img.shields.io/badge/Linux%20Foundation-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/cloud-hypervisor/cloud-hypervisor?style=flat-square&label=%20)
- [KubeVirt](https://github.com/kubevirt/kubevirt) - Full virtual machines as CRDs rather than a RuntimeClass, with live migration and device passthrough. Heavy for a code sandbox, but the answer when the workload needs a desktop, a GPU, or Windows. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs, heavy](https://img.shields.io/badge/native%20CRDs,%20heavy-8b949e?style=flat-square) ![Red Hat](https://img.shields.io/badge/Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kubevirt/kubevirt?style=flat-square&label=%20)
- [Confidential Containers](https://github.com/confidential-containers/operator) - An operator that pairs Kata with a hardware TEE, so sandbox memory is opaque to the host as well. For regulated workloads where the cloud provider sits outside the trust boundary. ![separate + TEE](https://img.shields.io/badge/separate%20%2B%20TEE-8250df?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![Intel, IBM, Red Hat](https://img.shields.io/badge/Intel,%20IBM,%20Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/confidential-containers/operator?style=flat-square&label=%20)

WebAssembly is a fourth option on a different axis: no kernel to escape, but no arbitrary Linux binaries either. See [runwasi](https://github.com/containerd/runwasi) and [WasmEdge](https://github.com/WasmEdge/WasmEdge).

## On Kubernetes

Projects that make a sandbox a first-class cluster resource. They do not isolate anything themselves — they pick a runtime from above and manage lifecycle, identity, and storage around it.

- [agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox) - The emerging standard, under SIG Apps. Four CRDs give a sandbox stable identity, persistent storage, and a warm pool, while isolation is delegated to whichever RuntimeClass you point it at. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![native CRDs, v0.x](https://img.shields.io/badge/native%20CRDs,%20v0.x-8b949e?style=flat-square) ![Google, Red Hat](https://img.shields.io/badge/Google,%20Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kubernetes-sigs/agent-sandbox?style=flat-square&label=%20)
- [OpenSandbox](https://github.com/opensandbox-group/OpenSandbox) - A complete platform rather than a bare API: five language SDKs, an MCP server, a credential vault, and per-sandbox egress control, over either Docker or Kubernetes runtimes. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![Alibaba](https://img.shields.io/badge/Alibaba-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/opensandbox-group/OpenSandbox?style=flat-square&label=%20)
- [CubeSandbox](https://github.com/TencentCloud/CubeSandbox) - Tencent's internal stack, open-sourced in 2026 after large-scale production use. A one-click script deploys it without a cluster at all, which makes it unusually cheap to evaluate. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs or none](https://img.shields.io/badge/native%20CRDs%20or%20none-8b949e?style=flat-square) ![Tencent Cloud](https://img.shields.io/badge/Tencent%20Cloud-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/TencentCloud/CubeSandbox?style=flat-square&label=%20)
- [OpenKruise Agents](https://github.com/openkruise/agents) - Ten CRDs extending the SIG API, plus an E2B-compatible server so existing E2B clients can target your own cluster. Note that pause deletes the Pod — in-memory state does not survive it. ![any runtime, unproven](https://img.shields.io/badge/any%20runtime,%20unproven-0969da?style=flat-square) ![10 CRDs](https://img.shields.io/badge/10%20CRDs-8b949e?style=flat-square) ![Alibaba Cloud](https://img.shields.io/badge/Alibaba%20Cloud-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/openkruise/agents?style=flat-square&label=%20)
- [mitos](https://github.com/mitos-run/mitos) - Restores Firecracker VMs from memory snapshots in milliseconds and forks them on Kubernetes, aimed at fan-out workloads where every branch starts from the same warm state. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![mitos-run](https://img.shields.io/badge/mitos--run-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/mitos-run/mitos?style=flat-square&label=%20)

### Adjacent layers

> Cluster-side projects often mistaken for sandboxes. Neither isolates a workload on its own; both are worth pairing with something that does.

- [vCluster](https://github.com/loft-sh/vcluster) - Gives each tenant a virtual control plane with its own API server and CRDs. That isolates the control plane, not the workload — pair it with a real runtime rather than relying on it alone. ![control plane only](https://img.shields.io/badge/control%20plane%20only-6e7781?style=flat-square) ![Loft Labs](https://img.shields.io/badge/Loft%20Labs-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/loft-sh/vcluster?style=flat-square&label=%20)
- [kagent](https://github.com/kagent-dev/kagent) - Kubernetes-native, but it orchestrates agents rather than isolating them — Agent, ModelConfig, and ToolServer CRDs, with isolation left to something else. Pairs with agent-sandbox rather than competing with it. ![not a sandbox](https://img.shields.io/badge/not%20a%20sandbox-6e7781?style=flat-square) ![pairs with agent-sandbox](https://img.shields.io/badge/pairs%20with%20agent--sandbox-8b949e?style=flat-square) ![Solo.io](https://img.shields.io/badge/Solo.io-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kagent-dev/kagent?style=flat-square&label=%20)

## Self-Hosted

Open source, and you can run it yourself — on a server, on a laptop, or on a cluster via Helm.

- [E2B](https://github.com/e2b-dev/E2B) - The most widely adopted agent sandbox SDK, on Firecracker with userfaultfd-backed lazy memory restore — which is how a paused sandbox resumes in tens of milliseconds. Self-hosting is Terraform, not Kubernetes. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![Terraform, not K8s](https://img.shields.io/badge/Terraform,%20not%20K8s-8b949e?style=flat-square) ![E2B](https://img.shields.io/badge/E2B-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/e2b-dev/E2B?style=flat-square&label=%20)
- [Daytona](https://github.com/daytonaio/daytona) - Fastest cold starts in the category, from pre-warmed Docker snapshots. Default isolation is a plain container, with Sysbox or Kata swappable in. The star count predates the pivot from dev environments. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![Helm](https://img.shields.io/badge/Helm-8b949e?style=flat-square) ![Daytona](https://img.shields.io/badge/Daytona-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/daytonaio/daytona?style=flat-square&label=%20)
- [microsandbox](https://github.com/superradcompany/microsandbox) - libkrun microVMs with sub-200ms starts, designed to run on a laptop rather than a cluster. A good fit when you want VM-grade isolation without operating any infrastructure. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your laptop](https://img.shields.io/badge/your%20laptop-8b949e?style=flat-square) ![Superrad](https://img.shields.io/badge/Superrad-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/superradcompany/microsandbox?style=flat-square&label=%20)
- [AIO Sandbox](https://github.com/agent-infra/sandbox) - Browser, shell, filesystem, MCP, and VS Code Server in a single container image, so an agent gets a whole workstation from one pull instead of wiring services together. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![Helm](https://img.shields.io/badge/Helm-8b949e?style=flat-square) ![ByteDance](https://img.shields.io/badge/ByteDance-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/agent-infra/sandbox?style=flat-square&label=%20)
- [forkd](https://github.com/deeplethe/forkd) - Brings `fork()` semantics to microVMs: 100 children from a warm parent in ~100ms, and a live VM can be branched mid-execution. Built for agent search and speculative execution. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![deeplethe](https://img.shields.io/badge/deeplethe-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/deeplethe/forkd?style=flat-square&label=%20)
- [gondolin](https://github.com/earendil-works/gondolin) - Linux microVMs with a TypeScript control plane, so the orchestration layer is scriptable in the same language as most agent frameworks. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![earendil.works](https://img.shields.io/badge/earendil.works-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/earendil-works/gondolin?style=flat-square&label=%20)
- [arcbox](https://github.com/arcboxlabs/arcbox) - Own kernel, filesystem, and network per agent, booting in under 200ms, for teams that want microVM isolation without assembling Firecracker plumbing themselves. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![Arcbox Labs](https://img.shields.io/badge/Arcbox%20Labs-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/arcboxlabs/arcbox?style=flat-square&label=%20)
- [pullrun](https://github.com/pullrun/pullrun) - Boots any OCI image as a Firecracker microVM, a Linux container, or an Apple virtualization VM — the same image at three isolation levels. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![pullrun](https://img.shields.io/badge/pullrun-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/pullrun/pullrun?style=flat-square&label=%20)
- [llm-sandbox](https://github.com/vndee/llm-sandbox) - Small Python library wrapping Docker, Podman, or Kubernetes behind one API. The quickest way to add code execution to an existing app, at container-level isolation. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![Docker, Podman, K8s](https://img.shields.io/badge/Docker,%20Podman,%20K8s-8b949e?style=flat-square) ![Community](https://img.shields.io/badge/Community-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/vndee/llm-sandbox?style=flat-square&label=%20)
- [SWE-ReX](https://github.com/SWE-agent/SWE-ReX) - Massively parallel sandboxed execution built for agent benchmarking, where hundreds of rollouts run at once and throughput matters more than per-sandbox isolation. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![Princeton NLP](https://img.shields.io/badge/Princeton%20NLP-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/SWE-agent/SWE-ReX?style=flat-square&label=%20)
- [SandboxFusion](https://github.com/bytedance/SandboxFusion) - Multi-language execution service for evaluation and reinforcement learning, with built-in support for a long list of programming-problem datasets. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![ByteDance](https://img.shields.io/badge/ByteDance-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/bytedance/SandboxFusion?style=flat-square&label=%20)
- [cua](https://github.com/trycua/cua) - Computer-use drivers and cross-OS fleets for agents that need a screen rather than a shell, with benchmarks for training and evaluation. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your laptop or cloud](https://img.shields.io/badge/your%20laptop%20or%20cloud-8b949e?style=flat-square) ![Cua](https://img.shields.io/badge/Cua-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/trycua/cua?style=flat-square&label=%20)
- [steel-browser](https://github.com/steel-dev/steel-browser) - Open-source browser API for agents: session management, proxy support, and debugging behind one REST interface. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![your server](https://img.shields.io/badge/your%20server-8b949e?style=flat-square) ![Steel](https://img.shields.io/badge/Steel-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/steel-dev/steel-browser?style=flat-square&label=%20)
- [sandbox-runtime](https://github.com/anthropic-experimental/sandbox-runtime) - Filesystem and network restrictions for a coding agent on your own machine, via Seatbelt on macOS and bubblewrap on Linux. Deliberately shared-kernel: the threat model is mistakes, not adversaries. ![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) ![your laptop](https://img.shields.io/badge/your%20laptop-8b949e?style=flat-square) ![Anthropic](https://img.shields.io/badge/Anthropic-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/anthropic-experimental/sandbox-runtime?style=flat-square&label=%20)

AGPL-3.0, which matters if you plan to embed it in a commercial product. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![your server, AGPL](https://img.shields.io/badge/your%20server,%20AGPL-8b949e?style=flat-square) ![Community](https://img.shields.io/badge/Community-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/abshkbh/arrakis?style=flat-square&label=%20)

## Managed Platforms

Hosted services. The middle badge is the one that matters here — almost none of them let you run the thing yourself.
