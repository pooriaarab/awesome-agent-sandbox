# Awesome Agent Sandbox [![Awesome](https://awesome.re/badge-flat2.svg)](https://awesome.re)

> Sandboxes for running untrusted, AI-agent-generated code.

LLM agents write and execute code nobody reviewed. A sandbox is what stands between that code and your kernel, your network, and your secrets.

Every entry is one sentence followed by three badges: **how it isolates**, **how you run it**, and **who backs it**. Colour is reserved for isolation strength, so scanning the coloured column is the comparison:

![shared kernel](https://img.shields.io/badge/shared%20kernel-d1242f?style=flat-square) weakest, shares the host kernel  ·  ![intercepted kernel](https://img.shields.io/badge/intercepted%20kernel-bf8700?style=flat-square) syscalls served in user space  ·  ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) strongest, own kernel in a VM  ·  ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) you choose  ·  ![separate + TEE](https://img.shields.io/badge/separate%20%2B%20TEE-8250df?style=flat-square) hides from the host too

## Isolation Runtimes

Three ways to isolate, weakest to strongest. Everything else in this list picks one, so these names are used throughout.

| Tier                   | How                                  | Overhead             | Run what               |
| ---------------------- | ------------------------------------ | -------------------- | ---------------------- |
| **Shared kernel**      | Namespaces, cgroups, syscall filters | None                 | Code you trust         |
| **Intercepted kernel** | Syscalls served in user space        | Moderate             | Code you mostly trust  |
| **Separate kernel**    | Own kernel in a virtual machine      | Boot time and memory | Code you did not write |

**Your own code needs a shared kernel at most. A stranger's needs a separate one.** The middle is a business decision, not a technical one.

Entries in this section carry a distinguishing fact instead of an isolation badge, since the subsection already states the tier.

### Shared kernel

> Same kernel as the host, fenced off with namespaces, cgroups, and syscall filters. Instant and cheap, but a kernel bug is a host compromise.

- [runc](https://github.com/opencontainers/runc) - The default, and the baseline this list measures against. ![the default](https://img.shields.io/badge/the%20default-8b949e?style=flat-square) ![OCI](https://img.shields.io/badge/OCI-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/opencontainers/runc?style=flat-square&label=%20)
- [Sysbox](https://github.com/nestybox/sysbox) - Hardened runc; the strongest option that still shares a kernel. ![Docker-in-Docker safe](https://img.shields.io/badge/Docker--in--Docker%20safe-8b949e?style=flat-square) ![Docker](https://img.shields.io/badge/Docker-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/nestybox/sysbox?style=flat-square&label=%20)
- [bubblewrap](https://github.com/containers/bubblewrap) - Unprivileged process sandboxing; a building block, not a platform. ![engine under Flatpak](https://img.shields.io/badge/engine%20under%20Flatpak-8b949e?style=flat-square) ![Red Hat](https://img.shields.io/badge/Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/containers/bubblewrap?style=flat-square&label=%20)
- [nsjail](https://github.com/google/nsjail) - Namespaces, cgroups, rlimits, and seccomp-bpf in one small tool. ![single binary](https://img.shields.io/badge/single%20binary-8b949e?style=flat-square) ![Google](https://img.shields.io/badge/Google-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/google/nsjail?style=flat-square&label=%20)

### Intercepted kernel

> Syscalls are reimplemented in user space and never reach the host kernel. No virtualization required, which is why it wins on managed Kubernetes.

- [gVisor](https://github.com/google/gvisor) - The only production option here. ![default on GKE](https://img.shields.io/badge/default%20on%20GKE-8b949e?style=flat-square) ![Google](https://img.shields.io/badge/Google-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/google/gvisor?style=flat-square&label=%20)

### Separate kernel

> Its own Linux kernel in a virtual machine. Nothing shared, so an exploit stays in the box. The baseline for code you did not write.

- [Firecracker](https://github.com/firecracker-microvm/firecracker) - The microVM that created this category. ![125ms boot](https://img.shields.io/badge/125ms%20boot-8b949e?style=flat-square) ![AWS](https://img.shields.io/badge/AWS-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/firecracker-microvm/firecracker?style=flat-square&label=%20)
- [Kata Containers](https://github.com/kata-containers/kata-containers) - Swappable VMM backends, and a TEE option when the host operator is in your threat model. ![most mature on K8s](https://img.shields.io/badge/most%20mature%20on%20K8s-8b949e?style=flat-square) ![OpenInfra](https://img.shields.io/badge/OpenInfra-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kata-containers/kata-containers?style=flat-square&label=%20)
- [Cloud Hypervisor](https://github.com/cloud-hypervisor/cloud-hypervisor) - Modern Rust VMM. ![Kata backend](https://img.shields.io/badge/Kata%20backend-8b949e?style=flat-square) ![Linux Foundation](https://img.shields.io/badge/Linux%20Foundation-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/cloud-hypervisor/cloud-hypervisor?style=flat-square&label=%20)
- [Edera Protect](https://edera.dev/) - Type-1 hypervisor per pod, unlocking instance types Kata cannot use. ![no HW virtualization needed](https://img.shields.io/badge/no%20HW%20virtualization%20needed-8b949e?style=flat-square) ![Edera](https://img.shields.io/badge/Edera-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/edera-dev/edera-agent?style=flat-square&label=%20)

WebAssembly is a fourth option on a different axis: no kernel to escape, but no arbitrary Linux binaries either. See [runwasi](https://github.com/containerd/runwasi) and [WasmEdge](https://github.com/WasmEdge/WasmEdge).

## Kubernetes-Native Sandbox Orchestrators

Projects that make a **sandbox** a first-class Kubernetes resource. They do not isolate anything themselves — they pick a runtime from above and manage lifecycle, identity, and storage around it.

Frameworks that orchestrate *agents* rather than sandboxes are under Related Projects.

- [agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox) - The emerging standard: four CRDs, warm pools, stable identity. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![native CRDs, v0.x](https://img.shields.io/badge/native%20CRDs,%20v0.x-8b949e?style=flat-square) ![Google, Red Hat](https://img.shields.io/badge/Google,%20Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kubernetes-sigs/agent-sandbox?style=flat-square&label=%20)
- [OpenSandbox](https://github.com/opensandbox-group/OpenSandbox) - Complete platform: five language SDKs, credential vault, per-sandbox egress control. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![Alibaba](https://img.shields.io/badge/Alibaba-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/opensandbox-group/OpenSandbox?style=flat-square&label=%20)
- [CubeSandbox](https://github.com/TencentCloud/CubeSandbox) - Production-proven stack that also deploys without a cluster at all. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs or none](https://img.shields.io/badge/native%20CRDs%20or%20none-8b949e?style=flat-square) ![Tencent Cloud](https://img.shields.io/badge/Tencent%20Cloud-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/TencentCloud/CubeSandbox?style=flat-square&label=%20)
- [OpenKruise Agents](https://github.com/openkruise/agents) - Superset of the SIG API that also speaks the E2B API, so E2B clients can target your own cluster. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![10 CRDs](https://img.shields.io/badge/10%20CRDs-8b949e?style=flat-square) ![Alibaba Cloud](https://img.shields.io/badge/Alibaba%20Cloud-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/openkruise/agents?style=flat-square&label=%20)
- [KubeVirt](https://github.com/kubevirt/kubevirt) - Full VMs as CRDs; the answer when a sandbox needs a GUI or Windows. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs, heavy](https://img.shields.io/badge/native%20CRDs,%20heavy-8b949e?style=flat-square) ![Red Hat](https://img.shields.io/badge/Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/kubevirt/kubevirt?style=flat-square&label=%20)
- [Confidential Containers](https://github.com/confidential-containers/operator) - For threat models where the cloud provider itself is untrusted. ![separate + TEE](https://img.shields.io/badge/separate%20%2B%20TEE-8250df?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![Intel, IBM, Red Hat](https://img.shields.io/badge/Intel,%20IBM,%20Red%20Hat-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/confidential-containers/operator?style=flat-square&label=%20)
- [vCluster](https://github.com/loft-sh/vcluster) - A virtual cluster per tenant; isolates the control plane, not the workload. ![any runtime](https://img.shields.io/badge/any%20runtime-0969da?style=flat-square) ![stack with a real runtime](https://img.shields.io/badge/stack%20with%20a%20real%20runtime-8b949e?style=flat-square) ![Loft Labs](https://img.shields.io/badge/Loft%20Labs-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/loft-sh/vcluster?style=flat-square&label=%20)
- [mitos](https://github.com/mitos-run/mitos) - Millisecond microVM forking from memory snapshots. ![separate kernel](https://img.shields.io/badge/separate%20kernel-1a7f37?style=flat-square) ![native CRDs](https://img.shields.io/badge/native%20CRDs-8b949e?style=flat-square) ![mitos-run](https://img.shields.io/badge/mitos--run-4a5568?style=flat-square) ![Stars](https://img.shields.io/github/stars/mitos-run/mitos?style=flat-square&label=%20)

agent-sandbox and OpenKruise Agents are complementary, not competing — the latter states it stays compatible with the SIG API and layers higher-level features on top.
